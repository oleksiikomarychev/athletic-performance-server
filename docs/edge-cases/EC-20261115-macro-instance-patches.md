## Условие и влияние

В будущей тренировке одна позиция каталога встречается дважды. После срабатывания правила пользователь должен увидеть конкретные экземпляры, подходы и изменения каждого. Прежний движок терял подходы при чтении упражнения и мог показать пустое предложение после успешного вычисления.

## Ожидаемое и фактическое поведение

Ожидается одно добавление в каждый выбранный экземпляр. На исходной версии даже при передаче внутреннего формата, ожидаемого движком, построитель непустого пакета возвращал `None`.

## Воспроизведение

- Версия: `2db1a364`. Для локальной пробы достаточно Python проекта, SQL/HTTP можно заменить синтетическим ответом.
- Загрузить исходный модуль через `git show 2db1a364:services/plans-service/plans_service/services/macro_engine.py`. Подставить `AsyncMock` вместо `_fetch_workout_details`, возвращающий `{7: {"exercises": [{"id": 2, "exercise_id": 8, "sets": [{"id": 9, "volume": 2}]}]}}`.
- Вызвать `_build_patches` для тренировки 7, действия `Adjust_Sets`, цели `exercise_ids=[8]`, режима `by_Value`, значения 1. Результат должен содержать одно добавление. Фактически получен `None`. Проба выполняется в памяти.

## Причина и исправление

Движок читал `exercises` вместо сериализованного `exercise_instances` и выходил из функции построения патчей без возврата результата. Адресация по одному определению упражнения также теряла различие экземпляров. Исправленный движок связывает workout, instance и set, накапливает последовательные изменения и передаёт полный пакет владельцу данных.
