# Proposal

## Why

На синтетической тренировке с десятью повторами условие `Total_Reps < 1` сработало из-за несовпадения имён полей между сервисами. При восстановлении входных данных движок построил изменение повторений для соседнего упражнения и потерял список изменений при возврате. Точечная правка одного из этих мест оставляет остальные дефекты в пути пользователя.

## What Changes

- Для `Adjust_Load`, `Adjust_Reps` и `Adjust_Sets` вычислять результат целиком для выбранных экземпляров упражнений и показывать его до записи. Существующий DSL и редактор остаются точками ввода.
- Исполнять подтверждённый пакет в транзакции workouts-service с проверкой исходного состояния, владельца и повтора. Для пустого результата, конфликта и недоступного источника возвращать различимые исходы.
- **BREAKING** Для записи изменений подходов клиенту потребуется идентификатор просмотренного результата. Прежнее подтверждение без него требует обновить preview.
- Отдельная работа потребуется для исполнения и восстановления `Inject_Mesocycle`. Существующую политику массовой правки и структуру RPE-таблицы этот change не пересматривает.

## Capabilities

### New Capabilities

- `applied-plan-set-macros` — вычисление, подтверждение и выполнение макросов подходов применённого плана.

### Modified Capabilities

Нет.

## Impact

Plans отвечает за правила и порядок применения, workouts за состояние тренировки, RPE и user-max за входные данные расчёта. Потребители включают gateway, Celery, генерацию подсказки после сессии, Flutter и AI-конструктор правил. Подробности DATA, EXEC, ACCESS, READY, COMPAT и повтора задачи описаны в design.md. Основания — [карта системы](../../../docs/architecture/system-map.md), [решение DATA](../../../docs/decisions/DEC-20261112-data-semantics-contract.md) и [решение EXEC](../../../docs/decisions/DEC-20261112-operation-execution-contract.md). Прежняя запись OBS-03 касается ошибки чтения. Отдельной записи edge case для потери списка изменений в просмотренном каталоге не найдено.

Дополнение от 2026-11-15 по запросу владельца — типизированное ядро переходов, проверки входного и выходного состояния, история с границами подходов, идентичность срабатывания и общий протокол конкурентной записи.
